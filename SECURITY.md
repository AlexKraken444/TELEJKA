# Безопасность TELEJKA

## Шифрование переписки

Новые сообщения в личных и групповых чатах шифруются на устройстве отправителя через Web Crypto: случайный AES-256-GCM для каждого сообщения, RSA-OAEP/SHA-256 (2048 бит) для передачи ключа каждому зарегистрированному устройству участников. ID чата включён в authenticated additional data. API отвергает новые незашифрованные сообщения. Сервер хранит ciphertext и зашифрованные ключи, но не приватные ключи устройств. Старые сообщения не переименовываются в зашифрованные: они остаются доступны как обычная история без отдельной подписи в интерфейсе.

Приватный ключ хранится в IndexedDB браузера и используется автоматически. Все участники должны открыть обновлённое приложение хотя бы один раз. Панели ручного управления и переноса ключей убраны из интерфейса по запросу владельца. Новое устройство получает последующие сообщения; старая зашифрованная история остаётся доступной на исходном устройстве. Очистка данных браузера может сделать эту историю недоступной.

При первой отправке браузер запоминает ключи участников (TOFU). Изменение списка блокирует отправку до подтверждения. В интерфейсе показывается только уведомление о новом устройстве с подтверждением продолжения переписки; ручная сверка отпечатков через интерфейс не доступна. Доверие первой загрузке приложения и первому получению ключей остаётся необходимым.

Это не протокол Signal: нет Double Ratchet, forward secrecy, цифровой подписи автора сообщения и независимого криптографического аудита. Компрометация приватного ключа раскрывает доступную этому ключу историю. Контроль сервера над выдаваемым JavaScript, XSS или заражение устройства могут нарушить защиту; метаданные (участники, время, размер файлов) серверу доступны. Нельзя представлять эту реализацию как защиту от всех возможностей злонамеренного сервера.

## Вложения

До 4 файлов по 25 МиБ, загрузка частями по 256 КиБ. В чатах файл шифруется отдельным AES-GCM ключом до загрузки; имя, MIME и ключ передаются внутри зашифрованного сообщения. API проверяет участника чата и владельца загрузки. В постах и комментариях разрешены только фото и видео; эти публикации доступны авторизованным пользователям и не шифруются сквозным способом. HTML/SVG не отображаются как активные документы. Фото и видео автоматически загружаются и показываются во встроенном окне при приближении к видимой области страницы. Видео запускается пользователем через встроенные элементы управления. Остальные файлы загружаются по нажатию. Файлы хранятся в PostgreSQL, не во временной файловой системе Vercel. Квота: 100 МиБ в сутки и 1 ГиБ на аккаунт; незавершённые загрузки также учитываются.

## Пароли и API

Пароли хешируются bcrypt с cost 12. Хэши переносятся из `public.users` в `telejka_auth.credentials`, старое поле очищается; вход и регистрация используют новую таблицу. Миграция транзакционная, с блокировкой и записью версии, существующие сессии сохраняются. Это отдельная схема той же физической базы, не отдельный сервер и не отдельная граница доступа. Для физической изоляции нужны отдельное подключение и роль БД; в текущем развёртывании их нет.

Cookie HttpOnly, SameSite=Lax, Secure в production. Сессии отзываются при выходе. SQL параметризован, origin проверяется для изменений. Чтения: 360/мин на аккаунт, изменения: 120/мин, части файлов: 1200/мин. Лимиты атомарно хранятся в PostgreSQL и действуют между экземплярами Vercel. Вход также ограничен по нормализованному имени и IP; регистрация — по IP. В режиме прокси backend видит IP frontend-функции, поэтому IP-лимиты могут быть общими для пользователей. Размер JSON ограничивается при потоковом чтении до 450 000 байт. Ответ 429 содержит Retry-After.

## Уведомления

При открытом приложении опрос раз в 5 секунд. Уведомления о сообщениях после обновления атомарно отмечаются доставленными до ответа API — повторная загрузка или другая вкладка не показывают их снова. Это at-most-once: потеря ответа после отметки может пропустить уведомление; само сообщение сохраняется. Уведомления не содержат текста переписки. Системный push при закрытом браузере не реализован.

## Развёртывание и проверка

Рабочая TELEJKA использует согласованный backend `https://1234news.vercel.app/api/telejka`, если собственная DATABASE_URL не задана. Прокси передаёт только cookie сессии TELEJKA и JSON; не передаёт сторонние cookies, не следует перенаправлениям. Backend-код также обновляется в репозитории 1234news. У standalone-установки должна быть своя PostgreSQL-база; прокси на backend владельца не является общедоступным сервисом для чужих копий проекта.

`npm run build` и `npm test` проверяют миграцию старого пароля, постоянные сессии, группы, шифрование/дешифрование, отказ при подмене ciphertext, чужих ключах и другом чате, дедупликацию сообщений/уведомлений, владение файлами, ограничения форматов и размеров, rate limit. Тестовые аккаунты создаются только во временной локальной базе.

## БАТОНчики, TELEJKA+ и управление контактами

- Ежедневный вход: 15 × число последовательных дней. После пропуска серия начинается заново. Дата определяется сервером по Europe/Moscow. Повторный запрос или вкладка не начисляют награду снова.
- Одно случайное задание в день: 10 сообщений, 3 поста или 1 комментарий. Прогресс считают серверные триггеры только после успешной записи. Награда — 30, получение однократное.
- TELEJKA+ стоит 100 БАТОНчиков за календарный месяц; покупка продлевает срок, автоматического списания нет. Начисления и покупки сериализованы блокировкой кошелька; покупки принимают idempotency UUID.
- До трёх разных реакций от пользователя на пост или сообщение. Для добавления нужна активная подписка; убрать свою реакцию можно после окончания подписки. Реакции — серверные метаданные, они не входят в сквозное шифрование текста сообщения.
- Закрытый профиль защищается на API: лента, комментарии, хэштеги и публичные вложения фильтруются по доступу. После окончания подписки профиль остаётся закрытым; его можно бесплатно открыть. Уже полученный контент нельзя отозвать с устройства получателя.
- Блокировка запрещает личные сообщения и просмотр публикаций в обе стороны. Участие в общей группе сохраняется; групповые сообщения остаются доступны её участникам.
- Удаление контакта скрывает разговор только у удалившего и сохраняет историю. Новое сообщение снова показывает разговор. Создатель удаляет группу для всех, остальные участники могут выйти.
- Галочки меняет только неизменяемый ID владельца из lib/verification.ts. Имя и наличие галочки не дают административных прав.
- Миграции verification-v1 и community-v1 применяются автоматически однократно под advisory lock. Новые переменные окружения не нужны.

Музыка профиля: один аудиофайл до 25 МБ (MP3/M4A/OGG/WAV/WebM), загрузка и замена только с активной TELEJKA+. Удаление доступно и после окончания подписки. Для прослушивания подписка не нужна; уже добавленный трек остаётся доступен после окончания подписки владельца. Закрытые профили и блокировки проверяются и для файла. Плеер не запускается автоматически. Переливающийся значок «+» показывается только при активной подписке; при prefers-reduced-motion анимация отключена.

## Защита голосовых звонков
Аудио: WebRTC DTLS-SRTP между двумя участниками; зашифрованное RSA/AES-GCM согласование с UUID вызова как AAD. Сервер видит участников, время, состояния и размеры конвертов, но не SDP и аудио. Код сравнения — 48 бит SHA-256 от отсортированных DTLS-отпечатков. Доверие ключам устройств наследуется от чатов; сравнение кода позволяет обнаружить подмену. Это не независимый криптографический аудит.

Создание требует членства в личном чате, разрешения контакта и зарегистрированного устройства. Приём атомарен и привязан к одному устройству. Посторонним данные вызова недоступны. Действуют общие API rate limits. Повтор создания с тем же UUID не отправляет новый push. Вызов без ответа истекает через 60 секунд; потеря heartbeat — через 45 секунд. Конверты удаляются при завершении/истечении. Микрофон запрашивается только при явном начале/приёме вызова, дорожки останавливаются при завершении.

Web Push реализован (предыдущая строка о его отсутствии устарела): VAPID-ключи сохраняются сервером, подписка связана с сессией; payload содержит только идентификаторы и тип события. Для звонка TTL 60 секунд. Доставка зависит от ОС, разрешений и фоновых ограничений. TURN необязателен для прямого соединения, но необходим для некоторых сетей; параметры описаны в README.
