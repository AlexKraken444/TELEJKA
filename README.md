# TELEJKA

Русскоязычная соцсеть и мессенджер на Next.js App Router. Готова к размещению на Vercel. Используется оригинальный логотип из `public/telejka-logo.png`.

Подробности шифрования, хранения ключей и ограничений: [SECURITY.md](SECURITY.md).

Текущее развёртывание использует backend владельца в проекте 1234news, если у frontend нет собственной строки подключения. Не требуется повторно заполнять пустую переменную frontend.

## Возможности

- Первый визит открывает регистрацию; авторизованный пользователь попадает в ленту.
- Регистрация по уникальному имени и паролю без телефона и почты. Имя нечувствительно к регистру. Описание и аватар необязательны.
- Без фотографии — первая буква имени и случайный пастельный цвет, который сохраняется в базе.
- Пароли хешируются bcrypt. Сессии хранятся в PostgreSQL, cookie — HttpOnly, SameSite=Lax и Secure в production. Срок сессии — 365 дней. Перезапуск приложения и новый деплой не разлогинивают пользователей при сохранении базы. Выход отзывает текущую сессию; очистка cookie или истечение года потребуют повторного входа.
- Общая лента и собственные посты, лайки, комментарии, удаление своего поста. Посты до 2000 символов, комментарии до 1000.
- Поиск людей по имени, редактирование профиля и аватара.
- Личные чаты и группы до 50 участников. Чужие чаты недоступны на уровне API. Сообщения до 4000 символов.
- Новые сообщения проверяются каждые 3 секунды, список чатов — каждые 5 секунд. В скрытой вкладке опрос приостанавливается. Для Vercel не нужен отдельный WebSocket-сервер.
- Адаптивный интерфейс для компьютера и телефона; групповой диалог с клавиатурной навигацией.

## Развёртывание на Vercel

1. В Vercel нажмите **Add New → Project** и импортируйте `AlexKraken444/TELEJKA`. Framework Preset: **Next.js**, Node.js: **24.x**.
2. Подключите **Neon Postgres** или другой PostgreSQL через **Storage / Marketplace**. База должна быть доступна из Vercel. Для production используйте TLS и строку подключения с `sslmode=require`.
3. Добавьте серверную переменную **DATABASE_URL** со строкой подключения. Если интеграция выдала `POSTGRES_URL`, скопируйте её значение в `DATABASE_URL`. Не используйте префикс `NEXT_PUBLIC_`. Добавьте переменную в нужные окружения; для Preview лучше использовать отдельную базу.
4. Таблицы создаются автоматически при первом обращении к базе. Вручную выполнять SQL не требуется. Команда `npm run db:migrate` остаётся доступной для предварительной настройки.
5. Нажмите **Deploy** (или **Redeploy**, если переменные добавлялись после первого запуска). Команда сборки — `npm run build`, каталог вывода определяет Next.js автоматически.
6. Откройте сайт, зарегистрируйте два аккаунта в разных браузерах и проверьте переписку. В этом репозитории при отсутствии своей базы используется согласованный backend владельца.

Приложение ищет непустую PostgreSQL-строку в `DATABASE_URL`, `POSTGRES_URL`, `POSTGRES_URL_NON_POOLING` и вариантах с префиксом, например `NEON_DATABASE_URL`. Пустая ручная переменная не перекрывает значение интеграции. Поиск выполняется только в окружении текущего проекта.

Схема идемпотентна для первичной установки и применяется автоматически во время работы приложения; одновременные запуски синхронизируются блокировкой PostgreSQL. Используйте отдельную базу для Preview. Изменения структуры после первого релиза нужно оформлять отдельными миграциями. Резервные копии настраиваются у провайдера PostgreSQL.

Документация: [Next.js](https://nextjs.org/docs), [базы данных на Vercel](https://vercel.com/docs/marketplace-storage).

## Локальный запуск

Нужен Node.js 24.x.

```sh
npm ci
```

Скопируйте `.env.example` в `.env.local`, заполните `DATABASE_URL` и выполните:

```sh
npm run db:migrate
npm run dev
```

Откройте http://localhost:3000.

### Без внешней базы (только разработка)

В первом терминале:

```sh
npm run db:local
```

В `.env.local`:

```dotenv
DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:5433/postgres
```

Во втором терминале — `npm run dev`. Локальный PGlite хранит данные в `.local-db/`, папка исключена из Git. Он не используется и не запускается на Vercel.

## Проверки

```sh
npm run typecheck
npm run build
npm test
npm audit
```

Интеграционный тест использует отдельную временную PostgreSQL-совместимую базу PGlite на порту 5434 и production-сборку на порту 3101. Он проверяет регистрацию, дубликаты имён, cookie, вход и выход, посты, лайки, комментарии, права удаления, личные и групповые сообщения, запрет доступа посторонним, защиту от запросов с чужого origin и изменение профиля. Перед `npm test` выполните сборку. Тестовая база удаляется после завершения теста.

## Устройство проекта

- `app/` — страницы, стили и серверный API.
- `components/` — интерфейс регистрации, ленты, профиля и переписки.
- `lib/` — подключение к БД, авторизация, валидация и типы.
- `db/schema.sql` — схема PostgreSQL и индексы.
- `scripts/` — миграция и локальная база.
- `tests/` — проверки валидации и сквозные API-сценарии.

Параметризованные SQL-запросы, ограничения длины, проверка участников чата и авторства поста выполняются на сервере. Ограничения частоты запросов хранятся в БД и работают между экземплярами Vercel. Аватары преобразуются в WebP 256×256 и хранятся в PostgreSQL, поэтому не пропадают при перезапуске функции.

## Границы текущей версии

Есть сквозное шифрование новых сообщений и файлов, медиа в постах и комментариях, тёмная тема и уведомления внутри приложения. Ключи используются автоматически; старая зашифрованная история доступна на устройстве, которое её получало. Светлая тема включена по умолчанию, фото и видео показываются прямо в публикациях и чатах. Нет восстановления забытого пароля, системного push при закрытом приложении, звонков и добавления участников в уже созданную группу. Ограничения модели шифрования и логической изоляции хэшей описаны в SECURITY.md.

Просроченные сессии и записи лимитов можно периодически очищать в SQL Editor:

```sql
DELETE FROM sessions WHERE expires_at < now();
DELETE FROM rate_limits WHERE resets_at < now();
```

Реальные секреты и локальные данные не должны попадать в Git. `.env.local`, `.local-db`, `node_modules` и `.next` исключены через `.gitignore`.

### Системные уведомления
В профиле включите «Уведомления на устройстве» и разрешите запрос браузера. Каждое устройство подключается отдельно (до пяти). Web Push работает через service worker при закрытой вкладке; на iPhone/iPad требуется установленное на главный экран веб-приложение (iOS 16.4+). Принудительное завершение браузера, системный запрет уведомлений и ограничения фоновой работы могут препятствовать доставке.

VAPID-ключи создаются один раз автоматически и сохраняются в telejka_auth.push_keys; дополнительные переменные окружения не нужны. Подписки связаны с сессией: выход из аккаунта отзывает серверную подписку. Сервер отправляет только «Новое сообщение» и идентификаторы для открытия чата, без содержимого переписки. Разрешены только HTTPS endpoints известных push-провайдеров. При ошибках сети выполняется до трёх попыток; просроченные подписки удаляются. Push-служба может хранить уведомление до суток. Успешная отправка учитывается для предотвращения повторных уведомлений внутри сайта.

Проверки: API регистрации/удаления подписок, отзыв при выходе, сохранение VAPID-ключа, ограничения endpoints, обработчик service worker и ссылки на чат. Фактическая доставка при закрытом браузере требует разрешения уведомлений на конкретном устройстве и отдельно проверяется на нём.

Установка на телефон: кнопка сверху страницы регистрации вызывает доступный системный диалог Android; при отсутствии диалога показывает шаги меню браузера. На iPhone используется Safari → Поделиться → На экран Домой. Это веб-приложение с иконкой, без APK/IPA и магазинов. На ПК большой блок загрузки убран; новая Windows-сборка открывает обычную вкладку.
